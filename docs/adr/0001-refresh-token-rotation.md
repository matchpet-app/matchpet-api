# Hash, rotação e detecção de reuso do refresh token

O refresh token guardado em `refresh_tokens.secretHash` é um valor aleatório de alta entropia (`crypto.randomBytes(32)`, codificado em base64url), não um segredo de baixa entropia escolhido por humano como uma senha. Por isso ele é hasheado com **SHA-256**, não bcrypt: a lentidão proposital do bcrypt existe pra defender contra força bruta em segredos de baixa entropia, o que não se aplica aqui (256 bits já é inviável de força bruta), e o SHA-256 sendo determinístico permite que o `/auth/refresh` busque o token direto pelo `secretHash`, em vez de comparar contra cada linha da tabela.

A cada `/auth/refresh`, a linha atual é marcada com `revokedAt = now()` e uma **linha nova é inserida** — o `secretHash` nunca é sobrescrito no lugar. Isso é necessário pra detecção de reuso funcionar: se um token antigo, já rotacionado, for apresentado de novo (sinal de que o token foi roubado e tanto o ladrão quanto o usuário legítimo o usaram), a busca ainda encontra a linha (agora com `revokedAt` preenchido) e consegue distinguir "reuso de um token já consumido" (comprometimento — revoga todos os tokens daquele `userId`) de "token que nunca existiu" (simplesmente inválido). Sobrescrever no lugar perderia o hash antigo e tornaria essa distinção impossível.

**Limitação conhecida, aceita deliberadamente:** chamadas de refresh concorrentes na mesma sessão (ex.: duas abas do navegador disparando refresh-on-401 no mesmo instante) podem gerar um falso positivo de detecção de reuso e deslogar o usuário legítimo, já que a segunda requisição apresenta um token que a primeira já rotacionou. Optamos por não adicionar uma janela de graça pra esse caso (ex.: tratar reuso do mesmo hash dentro de N segundos como uma corrida benigna e reemitir o mesmo token novo) porque isso adiciona complexidade real no trecho de código mais sensível de segurança do app, pra um modo de falha cujo custo é "o usuário ocasionalmente precisa logar de novo" — julgado não valer a pena para o perfil de risco deste app. Revisitar se o uso com múltiplas abas se mostrar comum e usuários reportarem logouts inesperados.
